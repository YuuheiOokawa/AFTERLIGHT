# AI素材・制作工程・受入基準

## 今回の実素材
assets/generatedに背景アトラス、キャラクターアトラス、UIアトラスの生成PNGを格納。計3枚からプログラムが参照するタイルを抽出してPNGとして格納する。生成は組込imagegen。プロンプト原文はassets/prompts.json、用途・生成元はassets/manifest.json。
背景4点：タイトル/ホーム、世界マップ、戦場、召喚門。
人物6点：リュカ、ガラン、セナ、ノア、イオ、星骸竜。
UI/武具9点：金ボタン、青パネル、カード枠、羅針盤、石、剣、盾、遺物、本。
文字と動的UI配置・ヒット領域・HPバー・エフェクトはコードで描画する。背景、人物、マップ、装飾、装備の視覚素材は生成AI。読みやすい日本語と機能まで一枚の生成画像へ焼き込むと実装に不向きなので、画像と操作レイヤーを分ける。

## 統一アート指示
未明の光を描く。紺の空、青緑の流れ、象牙の構造物、金の輪。未来を失った世界でも暗い絶望だけにしない。人体は成人の設定、既存IP固有の衣装・顔・ロゴを指定しない。主要人物は顔・配色・道具を固定した参照画像を用い、ポーズと表情を個別生成する。

## 製品用パイプライン
1. アートディレクション：世界、地域、属性、人物ごとの色・形・材質をstyle bibleへ記載。
2. 人物：立ち絵基準→表情4種→戦闘正面/側面→攻撃・被弾・必殺用差分。背景除去が必要なら生成時に透過を指定する。
3. マップ：地域コンセプト→実ゲームのノード配置と当たり判定を別データ化。現在のマップはノード移動型の背景であり歩行タイルではない。
4. UI：生成装飾を9-slice向けに整える。文字・操作はコード、枠・アイコンは画像。自動生成画像の線ずれ・枠厚をQAする。
5. ガチャ：門背景→R/SR/SSR用差分→時間停止カットイン→人物ボイス・SE。演出はタイムラインで画像を動かす。
6. 検証：余分な指、破綻した武器、同一人物の顔ぶれ、見切れ、透過縁、縮小時可読性、生成元と利用条件の記録。
7. 納品：asset_id、prompt、参照画像、generation_method、承認者、用途、hash、atlas座標、source PNGを保存。

今回の人物は胸像であり戦闘スプライトやLive2D/Spineリグは未制作。アトラスの均等区切りは試作に適するが本番は一素材一出力の個別生成と再検証を推奨する。

## 開発順（工数は概算仮説）
A：縦切り試作 4〜6週。1章、5体、1ボス、通常/必殺、ガチャ、ローカル育成。
B：オンライン基盤 6〜10週。認証、抽選/育成の権威化、台帳、引継ぎ、監査、復帰。
C：本編拡張 12〜24週。12章、敵と会話、素材試練、装備、30体の制作。
D：対人/運営 6〜12週。ギルド、フレンド、非同期アリーナ、運営ツール。
E：端末・ストアQA 4〜8週。性能、課金検証、配信、障害復旧。
期間は少人数チームでの検討幅であり、ひとりで全仕様を短期間に完成する約束ではない。画像生成時間だけで制作全体を見積もらない。

## 製品版受入基準
- 360px幅でも主ボタン44px以上、safe area内で最下部操作が見える。
- ホームから再開2タップ、指定クエスト3タップ、一括育成の選択は10体以上でもまとめ操作可能。
- 100回の二重送信で抽選/育成の通貨減算は各取引1回。
- 抽選の天井と10連保証、SSR確定予兆の不一致0件。
- 戦闘中の連打で同キャラ二重行動・負のゲージ・ターン飛ばし0件。
- ギルド所属変更、友人申請競合、ブロック相手への招待を検証。
- PvP勝敗はサーバー再計算、リプレイ一致100%。
- 初見本編中央値36〜44時間。エンドコンテンツは月ごとに能動時間と離脱率を計測。

## 試作検証
qa/TEST_REPORT.mdに実際の確認結果を記載。画面PNGはscreensフォルダ。プログラム検証と画面確認で分けて記録し、製品版の40時間やオンライン負荷まで確認済みとは記さない。
